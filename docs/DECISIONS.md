# Decisions

Choices made where the brief was silent or ambiguous. Newest last.

| #   | Decision                                                                                                                                                                                                                                                                                                            | Why                                                                                                                                                                                           |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **Next.js 15.5** (not 16), React 19.2, Prisma 6.19, TypeScript 5.9, Zod 3.25, Tailwind 4                                                                                                                                                                                                                            | Brief says "Next.js 15+". 15.5 is the mature line Auth.js v5 and the rest of the stack are proven on; Prisma 7 and TS 7 are new majors with breaking changes.                                 |
| 2   | **Auth.js v5 beta** with JWT sessions                                                                                                                                                                                                                                                                               | Credentials provider requires JWT. A split edge-safe config (`src/lib/auth/config.ts`) keeps Prisma and argon2 out of middleware.                                                             |
| 3   | **@node-rs/argon2** for password hashing                                                                                                                                                                                                                                                                            | Prebuilt binaries, no native compile step; argon2id with OWASP parameters.                                                                                                                    |
| 4   | Magic links only for **existing** accounts                                                                                                                                                                                                                                                                          | Parents, applicants and staff are created by the school; no public sign-up surface.                                                                                                           |
| 5   | Fonts self-hosted from Fontsource files via `next/font/local`                                                                                                                                                                                                                                                       | Works offline, no runtime call to Google, Latin subset only (perf).                                                                                                                           |
| 6   | `/_design` lives at `src/app/%5Fdesign`                                                                                                                                                                                                                                                                             | App Router treats `_folders` as private; the URL-encoded underscore makes the route public.                                                                                                   |
| 7   | Rate limiting stored in Postgres (`RateLimitHit`)                                                                                                                                                                                                                                                                   | Works across server instances without adding Redis to a demo. Swap for Redis/Upstash at scale.                                                                                                |
| 8   | Image captcha is SVG generated on the server; token = HMAC(answer, nonce) + expiry; single use                                                                                                                                                                                                                      | No third-party dependency; answer never sent to the client.                                                                                                                                   |
| 9   | Mock gateway mirrors Razorpay conventions (`order\|payment` HMAC, webhook HMAC over raw body)                                                                                                                                                                                                                       | Downstream code is identical for mock and real gateways.                                                                                                                                      |
| 10  | Webhook handler idempotency is two-layered: unique `(provider, eventId)` **and** unique `providerPaymentId`                                                                                                                                                                                                         | A replayed event with a new id still can't double-credit.                                                                                                                                     |
| 11  | Registration fee is never put on the annual invoice                                                                                                                                                                                                                                                                 | It is collected at registration through its own order.                                                                                                                                        |
| 12  | Concessions apply in priority order on the _remaining_ amount; an exclusive concession only applies if nothing was applied before it and blocks everything after                                                                                                                                                    | Deterministic and explainable line by line ("why is my discount ₹X?").                                                                                                                        |
| 13  | Late fee is recomputed absolutely each night and never lowered                                                                                                                                                                                                                                                      | Idempotent job; a part-payment doesn't erase a fee that was already charged. Waiver is explicit, permissioned and audited.                                                                    |
| 14  | Advance rebate applies only to single-instalment plans due on/before the rebate date                                                                                                                                                                                                                                | Matches "rebate if paid in full by date"; forfeited by the nightly job if unpaid by then.                                                                                                     |
| 15  | Refund policy defaults: new pupil 100 % of refundable heads before the session starts, 0 % after; existing pupil pro-rata unconsumed share minus one term (33.33 %) in lieu of < 90 days' notice                                                                                                                    | Configurable in Settings → Fees; sample values only.                                                                                                                                          |
| 16  | Announcement bar and events are **database-backed** (seeded from `content/*.json`)                                                                                                                                                                                                                                  | The brief asks for both "driven from content JSON" and "editable in content admin". The JSON is the seed and the fallback if the database is unreachable.                                     |
| 17  | Mock email/WhatsApp/SMS adapters don't store anything themselves; the shared notify layer writes the `Outbox` row for every channel and provider                                                                                                                                                                    | One audit trail regardless of provider; the mock "inbox" is just the outbox.                                                                                                                  |
| 18  | The `frontend-design` and Impeccable skills referenced in the brief were not installed in the build environment                                                                                                                                                                                                     | Design decisions were made directly and recorded in `docs/DESIGN_SYSTEM.md`.                                                                                                                  |
| 19  | Fonts self-hosted via plain `@font-face` (not `next/font`)                                                                                                                                                                                                                                                          | `next/font` preloads every file of a family; preloading italics competed with the LCP image on mobile. Manual faces let us preload only the two upright files.                                |
| 20  | Enquiry drawer, Open House modal and mobile menu are code-split and mount on first use                                                                                                                                                                                                                              | Keeps Radix Dialog, react-hook-form and Zod (~50 kB) out of every page's first load.                                                                                                          |
| 21  | Route transition only after client-side navigation                                                                                                                                                                                                                                                                  | A fade-in on first load delays LCP (Chrome ignores opacity-0 paints).                                                                                                                         |
| 22  | Honeypot field is accepted by the schema and silently "succeeds"                                                                                                                                                                                                                                                    | Rejecting it with a validation error tells bots which field to leave empty.                                                                                                                   |
| 23  | All dates are formatted in IST with `@date-fns/tz`; date-only values are stored as UTC midnight                                                                                                                                                                                                                     | Server and visitor timezones vary; the school's calendar doesn't. Financial-year boundaries are also computed in IST.                                                                         |
| 24  | E2E runs against its own Next server (`NEXT_DIST_DIR=.next-e2e`, port 3100, `CAPTCHA_PROVIDER=none`, `E2E=1` disables rate limiting)                                                                                                                                                                                | Coexists with `pnpm dev`; the image captcha is covered by unit tests instead.                                                                                                                 |
| 25  | Fee pages show the next admissions year by default with a switch to the current year                                                                                                                                                                                                                                | Families reading fee pages are mostly applying for next year.                                                                                                                                 |
| 26  | PDFs use built-in Helvetica/Times and print "Rs." instead of "₹"                                                                                                                                                                                                                                                    | Standard PDF fonts lack the rupee glyph; avoids shipping TTFs.                                                                                                                                |
| 27  | 360° viewer: Photo Sphere Viewer v5 with the Virtual Tour plugin in `renderMode: "2d"` and manual yaw/pitch links                                                                                                                                                                                                   | Works with any equirectangular image; hotspot positions live in `content/tour.json`.                                                                                                          |
| 28  | Dashboard charts are a small in-house kit (`src/components/charts`): HTML/CSS bars and meters with a thin client hover layer, no chart library                                                                                                                                                                      | Five chart forms cover the CRM; this keeps ~100 kB of charting JS out of the admin bundle, renders on the server, and lets every mark follow the design tokens. `recharts` was removed.       |
| 29  | Chart colours are their own tokens (`--viz-*`), derived from the damson/marigold ramps and checked with a palette validator (lightness band, chroma floor, colour-blind separation, contrast) in light and dark                                                                                                     | Brand colours picked by eye failed: kiln and marigold are indistinguishable for deuteranopes. Two categorical slots plus a 7-step damson ordinal ramp (funnel stages) pass every gate.        |
| 30  | Every chart ships a Chart/Table toggle, keyboard-focusable marks with tooltips, and written values                                                                                                                                                                                                                  | Colour is never the only channel; the table is the screen-reader and print equivalent.                                                                                                        |
| 31  | One dashboard per role focus (overview, admissions, finance, registrar, teaching, boarding, people); each widget's data is also permission-gated                                                                                                                                                                    | A Principal and a Houseparent need different first screens; hiding UI is not the control, so the queries check permissions too.                                                               |
| 32  | Password and demo sign-in redirect straight to the role's home from the server action                                                                                                                                                                                                                               | A server-action redirect into a route handler (`/login/continue`) is not followed by the client router: the browser stopped on `/login/continue`. Magic links (full-page loads) still use it. |
| 33  | "Places for next year" = section capacity − pupils moving up from the class below − accepted places (fee paid / admitted) − open offers                                                                                                                                                                             | Gives Admissions a live, honest seat count without a separate seats table. Sections are small (8–10 per section, 18 in Sixth Form), which suits the school's size.                            |
| 34  | The demo seed is consistent end to end: nothing is dated in the future, staff actions fall in office hours (IST), applications are paired with the enquiry they came from (same child, class and boarding wish), timetables are clash-free with a teaching-load cap, and the outbox is filled by the real templates | A pitch audience clicks around; one impossible date or a Year 1 child aged 13 undermines trust in the whole system.                                                                           |
| 35  | Fee revisions reprice open invoices **forwards**: settled instalments keep their amounts, the difference is spread over what is still to pay, overpaid principal becomes a credit                                                                                                                                   | Re-spreading payments oldest-first (the simpler model) would re-open an instalment the family already settled — and could make it overdue with late fees overnight.                           |
| 36  | Revisions are previewed against every affected open invoice before publishing, and publishing is one transaction (supersede, activate, reprice, audit)                                                                                                                                                              | Finance staff see exactly what changes for whom; a failure half-way can't leave the website and invoices on different versions.                                                               |
| 37  | Maker–checker for refunds and discretionary concessions is enforced in the service layer (requester ≠ approver)                                                                                                                                                                                                     | The UI hides the button, but the rule must hold for API calls and scripts too.                                                                                                                |
| 38  | Reconciliation matches by reference first, then by amount and date **only when exactly one payment fits**                                                                                                                                                                                                           | Two identical cheques in a week are common in a school; guessing between them silently mis-reconciles.                                                                                        |
| 39  | Cron jobs are plain authenticated routes (`/api/cron/*`, `Bearer CRON_SECRET`, constant-time compare) scheduled by `vercel.json`                                                                                                                                                                                    | Works on Vercel, GitHub Actions or a VM's crontab; every job is idempotent so retries are safe.                                                                                               |
| 40  | Admin forms submit through `onSubmit` + `FormData`, not React 19 form `action`s                                                                                                                                                                                                                                     | React resets uncontrolled fields after any form action, including a failed one — a validation error wiped the reference the user had typed.                                                   |
| 41  | A manual payment dated "today" is stamped now; earlier dates at midday IST                                                                                                                                                                                                                                          | Midday IST "today" can be in the future in the early hours, and the server rightly refuses future-dated payments.                                                                             |
| 42  | A parent keeps read-only access to a child who has left (fees, receipts, documents outlive enrolment); pocket-money top-ups and new requests are blocked for her                                                                                                                                                    |
| 43  | Circulars store their audience (everyone, boarders, or a class) and the portal only shows a family the circulars meant for them                                                                                                                                                                                     |
| 44  | Family requests are visible and answerable only by roles that handle that kind (withdrawal and profile: `students:write`; concession: concession permissions; pocket money: `imprest:write`)                                                                                                                        |
| 45  | Pupils ticked "Repeat" at promotion move into next year in their own class; the year switch is refused while pupils are still placed in the outgoing year                                                                                                                                                           |
| 46  | Imprest balance checks and inserts share one transaction behind a per-pupil advisory lock, so two purchases can't both pass the check                                                                                                                                                                               |
| 47  | Deploys load the demo school from `prisma/snapshot/demo.sql.gz` in one transaction instead of running the seed: the seed sends thousands of queries and takes hours across a region boundary                                                                                                                        |
| 48  | A marker row in `Setting` records that the snapshot was loaded; redeploys never touch existing data. `SEED_ON_BUILD=always` or the super admin's Reset on `/demo` reloads it                                                                                                                                        |
| 49  | On Vercel, uploads use `/tmp` (not durable) and the mock gateway delivers its signed webhook in-process, so the demo needs no object store and no self-calls                                                                                                                                                        |
| 50  | The staff application is one JSON document (`StaffApplication.data`) validated by shared per-step Zod schemas on client and server; the resume token is returned once and only its hash is stored                                                                                                                   |
| 51  | Reports are built once as typed tables; the page, the CSV and the XLSX all render the same tables, and every chart reads from its table                                                                                                                                                                             |
| 52  | The OpenAPI document is generated from the route handlers (method, path, doc comment, permission) and a unit test fails when the committed copy is stale                                                                                                                                                            |
| 53  | Wide tables that can scroll sideways are labelled, focusable regions (`Table scrollLabel`), so keyboard users can reach them                                                                                                                                                                                        |
| 54  | Sign-in and draft-resume links are scrubbed from the Outbox once delivered with a live provider; demo accounts can't sign in with a password or link unless demo mode is on                                                                                                                                         |
| 55  | The deploy build loads demo data only in demo mode, only into an empty or demo-marked database, and the Reset action only runs on a marked database, with a cooldown                                                                                                                                                |
| 56  | Direct-to-store (S3) uploads are validated after the fact through `POST /api/uploads/complete`; a rejected file is deleted from the bucket                                                                                                                                                                          |
